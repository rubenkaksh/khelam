- **Web auth = in-memory session (2026-08-11):** web now mirrors the macOS precedent — `persist: !kIsWeb && !Platform.isMacOS`. Web refreshes lose the login; HTTPS/localhost persistence via flutter_secure_storage was considered but the plugin throws `UnsupportedError` on any non-secure origin, so in-memory is the low-effort correct default. If real web persistence is wanted later, use shared_preferences (localStorage) behind a conditional import — that's a separate follow-up.
- **Dark scheme seed = light seed (2026-08-11):** dark now derives from `AppPalette.primary` (#097339, same as light) instead of the legacy teal `AppPalette.seed` (#1A5F7A); dropped the `primary: AppPalette.surfaceTintDark` (light-blue #8ECAE6) override so the dark primary is seed-derived. Dark is now the green family like light — complementary brightnesses. All 11 audited dark pairs pass (≥4.51:1). `surfaceTintLight`/`surfaceTintDark` now unused in khelam (kept, documented).
- **Web persistence advisory answered (2026-08-11):** user asked "how would you secure the token if it's localStorage?" — answer: you can't meaningfully (localStorage is XSS-readable; encryption key must live in JS-reachable storage too, which is exactly what flutter_secure_storage_web does). Real fix = httpOnly Secure SameSite cookie (+ CSRF) or short-lived access + rotating refresh cookie — both backend work (backend returns `{accessToken, user}` in JSON body, no refresh flow). Recommended app-side hardening: CSP on web build (no unsafe-eval; dart2js needs only wasm-unsafe-eval). **User decision: keep the in-memory fix, no further changes.**
